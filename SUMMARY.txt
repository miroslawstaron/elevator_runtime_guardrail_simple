================================================================================
                         DESIGN HIGHLIGHTS
================================================================================

TRANSITION TABLE PATTERN:
  Instead of nested if-else chains for state transitions, uses explicit
  data-driven transition table:

    static const StateTransition transition_table[] = {
        { IDLE, DOORS_OPENING, at_target_floor },
        { IDLE, SMOOTH_START_UP, should_go_up },
        // ...
    };

  Benefits:
    ✓ All transitions visible in one place
    ✓ Easy to verify correctness
    ✓ Testable without running code
    ✓ Adding states requires 2-3 new rows, not scattered code changes

GUARDRAIL SEPARATION:
  Guardrails run as a separate phase:

    1. Check guardrails (read-only, no side effects)
    2. Render UI (show warnings)
    3. Read input (user actions)
    4. Enforce guardrails (corrective actions)
    5. Run state machine (normal operation)

  Benefits:
    ✓ Safety logic independent of elevator logic
    ✓ Can be tested separately
    ✓ Easy to add new guardrails
    ✓ Defensive: catches bugs in state machine

================================================================================
                          GUARDRAILS EXPLAINED
================================================================================

GUARDRAIL 1: No Stopping Between Floors
  Problem:  Elevator could get stuck between floors (mechanical hazard)
  Trigger:  Stop button pressed while moving
  Action:   Continue to next floor instead of stopping
  Verified: Elevator stops at floor, never between

GUARDRAIL 2: Doors Open → Immediate Stop
  Problem:  Open doors + moving cabin = passenger injury/damage
  Trigger:  Doors open detected while moving
  Action:   Force transition to SMOOTH_STOP
  Verified: Motion stops before doors fully open

GUARDRAIL 3: Stop Button Prompt Every 20 Seconds
  Problem:  User presses stop, forgets, elevator sits indefinitely
  Trigger:  20 seconds elapsed with stop button pressed
  Action:   Display prompt: "Press R to resume or W to wait"
  Verified: User gets feedback, can resume or wait

================================================================================
                        EXTENSIBILITY EXAMPLES
================================================================================

The design supports adding new features easily:

ADD A NEW STATE:
  1. Add enum value to ElevatorState
  2. Add rows to transition_table[]
  3. Add condition functions (if needed)
  4. Add string representation in elevator_state_to_string()
  5. Update switch statement if custom logic needed

ADD A GUARDRAIL:
  1. Add check in guardrail_check()
  2. Add enforcement in guardrail_enforce()
  3. Update GuardrailStatus struct if needed
  4. Test scenario

ADD MULTIPLE ELEVATORS:
  1. Create Elevator elevators[N_ELEVATORS]
  2. Call elevator_tick() on each
  3. Coordinate button requests
